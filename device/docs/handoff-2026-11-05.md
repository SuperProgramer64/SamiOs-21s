# Historical handoff: initial logo-stage boots

English consolidation of the early notes; see the top-level README for current status.

The early system reached the Apple logo and progress bar with Apple launchd, backboardd and SpringBoard running. A short watchdog interval ended runs before first-boot work completed. The phone then returned to Android and the loader recovered kernel log text into pmsg.

The A21s is legacy non-A/B: boot is mmcblk0p18, 36 MiB. Only boot and guarded xnusys reservations were authorized write targets. S-Boot requires a raw Image, not a gzip kernel. Original boot/recovery images must be retained by the device owner.

The loader builds the Apple-style device tree, places the kernel in high physical memory, reads the payload from the eMMC reservation and arms its watchdog. Stage0 mounts the payload ramdisk as md1 and invokes HakiOS init, then real Apple launchd. The root is presented as a RAM-disk-style startup while data is read from the eMMC system image.

The early profile used one CPU, `mali=2 buttons=3 fb_beam=0`, and a 900-second feeding interval. Those values are historical: later profiles enable eight cores and a 180-minute interval. Writable HFS+ data, native wallpapers and the TD4150 driver were added later.

Raw logs are recovered from the eMMC reservation and pmsg in Android. Forced reset may lose retained RAM. The current launcher waits 30 seconds and a verified USB disconnection before requesting one XNU run; an older launcher should not be reused. The affected macOS USB modem driver previously panicked during a connected transition.

The common tree, A21s loader/device layer, A32 graphics reference and A217F touch reference have distinct responsibilities. Device-specific power or storage assumptions must not be transferred between MediaTek, Qualcomm and Exynos.
